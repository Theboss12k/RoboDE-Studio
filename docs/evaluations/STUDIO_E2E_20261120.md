# RoboDE Studio — first end-to-end evaluation (2026-11-20)

What was run, on what, and what it showed. Every result below is labelled as one of: **real model inference**
(Claude through the Claude Code CLI), **real web** (live search or download), **fixture test** (scripted model
answers, mocked downloads) or **numeric simulation** (Studio's own kinematics and static-load code). Nothing was run
on a physical robot, in Isaac, in Gazebo, or with a dynamics engine.

## Setup

- Studio at this date, macOS, Python 3.13 venv, `npm run dev` (API 127.0.0.1:8800, UI 127.0.0.1:5190), the in-app
  browser pane for the UI.
- LLM profiles: default roles. Opus 5.5 for `spec`, `robot` and `revise`; Sonnet 5.5 for `scene`, `search`,
  `extract` and `analysis`.
- Task brief: "Move a 300 g bottle from point A to point B on a table, about 10 per minute."

## Defects the real runs found (all fixed the same day; regression tests use the saved real outputs)

1. The Claude CLI's strict `--json-schema` rejected `prefixItems`, which pydantic emits for `(x, y, z)` tuples.
   `ask_json` now converts fixed-length tuples to arrays with min/max items for every provider.
2. Every action's `duration_s` counted as dwell. The model gave every step a duration summing to the whole cycle, so
   the requirements asked for 5.3 m/s and 47 m/s². Now only wait, inspect and press count as dwell, capped at 50 %
   of the cycle.
3. A `move` sent the tool to the table surface, so the tool collided with the table at t = 0 and during the carry.
   It now goes to carry height. Held objects follow the grasp offset in the viewer.
4. The simulated run went as fast as the joint limits allowed (1.6 s for a 6 s cycle). The motion now stretches to
   fill the cycle, and the check reports the fastest feasible time.
5. Implausible ratings (15.4 m/s TCP, 1401°/s joints) were accepted. Family caps now apply to every source except
   numbers the user asked for.
6. A requested base move was dropped by the pipeline. The `robot_base` spec marker is now the single source of
   truth, and the scene must provide a mounting surface.
7. A faster cycle wasn't met because joint speeds were never re-sized. A short sizing loop now raises them, within
   caps.
8. The reach sizing rule double-counted height, which oversized the arm. It was rewritten, and revisions re-size
   instead of inheriting old lengths.
9. Search: prices without a publication date were dropped (now stamped "seen <date>"), candidates were oversized,
   and images and datasheet links were missing (now og:image and a product-page fallback).
10. Analysis counted unpublished family defaults as passes, ignored the verified TCP speed, and its comparison
    called passed checks "not available". Every candidate parameter now has a provenance. Checks that rest on
    unpublished values get no verdict.

## Fixture tests

`npm test`: 124 passed, 4 skipped. The skipped tests are the real-Claude test (`STUDIO_CLAUDE=1`) and the 3 web
tests (`STUDIO_WEB=1`, which passed when run once). They cover:

- physics against hand calculations;
- FK(IK(x)) for every family;
- generated URDFs re-parsing;
- task simulation for the bottle, pallet and mobile delivery tasks;
- agent validators;
- the API flow from brief to export;
- revision keeping v1;
- quote verification rejecting invented values;
- the SSRF guard with pinned addresses;
- regressions from the saved real outputs (`tests/fixtures/real_*.json`).

## Limits that still apply

- Checks are kinematic and static-load calculations: reach, joint limits, static torques, speeds, cycle time and
  coarse capsule collisions. There is no dynamics, no contact physics and no controller. Collisions are reported,
  not avoided.
- Only serial arms, gantries, mobile bases and mobile manipulators can be modelled. SCARA and delta robots are
  listed but not analysed.
- Search coverage varies by run. Run 2 returned 2 candidates, although up to 6 were asked for. Many industrial
  robots have no public price. Prices are dated web estimates, not quotes.
- The search model reads web pages through the provider's own tools. Only downloads that Studio's code makes go
  through the SSRF guard.
- Candidate link lengths are scaled from the published reach when the manufacturer doesn't publish them, and are
  labelled "derived".
- Gemini adapters were copied from the Testbed but not run here.
- Nothing was tested on hardware.
